# Lichii RX 6600 / Debian 13 — Integration audit, 2026-11-06

This is an evidence-based **candidate selection**, not a claim that the combined code has been built or played on RX 6600. Keep each build on a separate branch and use an isolated cache for A/B comparisons.

- The last public binary release **at audit time** was build-88 (`55532f2d814215aaf32a76c214cf129f2cb6282b`): it does **not** include #273.
- Checked 157 upstream branches across two branch-list pages, the current open PR list and the most recently updated PRs. Some branches are stale, experimental, unrelated to this GPU, or contain changes already merged; no bulk merge is advisable.

## Root cause from the user's GDB session

- `SIGSEGV` is on thread `VkPipelinePrebu`, in `/lib/x86_64-linux-gnu/libvulkan_radeon.so`, called from `Vulkan::vk::Device::CreateGraphicsPipeline`, `Vulkan::GraphicsPipeline::MakePipeline`, and prebuild.
- Dynarmic's process-wide SIGSEGV handler is why the emulator log mentions Dynarmic; this is not evidence of a CPU JIT crash.
- https://github.com/zortos293/Lichii/issues/236 reproduces an invalid SPIR-V depth-compare module causing a RADV crash. PR #273 fixes that **class** of depth-sampling bug, plus atomic retries and certain compiler stalls.
- A successful launch with #273 is encouraging but is not long-session stability proof.

## Deliberately excluded

- [#259](https://github.com/zortos293/Lichii/pull/259) `EDEN_NX2_PREFLUSH=1`: very large FPS improvements on one RTX 5060, **but visual flicker**; not appropriate as a stability default.
- [#267](https://github.com/zortos293/Lichii/pull/267) 60 FPS aggregate: measured on Ryzen 9 9950X3D / RTX 4080 and bundles many other PRs and experiments. Do not merge wholesale or claim the same FPS on Ryzen 7 5700G / RX 6600.
- [#268](https://github.com/zortos293/Lichii/pull/268) texture budget: designed for 16 GB GPUs, intentionally unchanged around 8 GB. Not useful for this RX 6600.
- [#253](https://github.com/zortos293/Lichii/pull/253) NVIDIA DLSS: not a RADV/RX 6600 path.
- [#216](https://github.com/zortos293/Lichii/pull/216) real-time game patch: may overlap the already bundled Dynamic FPS mod; requires separate compatibility evaluation.
- [#270](https://github.com/zortos293/Lichii/pull/270) FPS limit: quality-of-life, not an FPS gain on a system currently below 60 FPS.
- [#192](https://github.com/zortos293/Lichii/pull/192) mesh disk cache: baseline build-88 already added task/mesh persistence; do not reapply the older overlapping change.
- [#277](https://github.com/zortos293/Lichii/pull/277) Eglantine sync: closed without merging; its Vulkan scheduler race changes merit separate testing but not blind inclusion.
- Windows-only AV1/MinGW and Intel-specific code: out of scope.

## Build profiles / performance controls

The local script `build_lichii_rx6600.sh` creates separate branches named `rx6600/{stable,balanced,lab}-20261106` in a **separate clone** of the fork. It fetches exact upstream PR commits, cherry-picks with the original author and `-x`, compiles with Ninja/GCC and 8 jobs, and runs the tests by default. It does not force-push, wipe the working tree, or modify `~/dev/Lichii`.

Launch with a separate XDG cache directory per profile. Shader compilation will be cold on the first run, so warm up the same scene before benchmarking. Keep identical Vulkan, resolution, GPU accuracy, display/presentation settings, and OoT game version. Record actual gameplay FPS, stutters, graphical anomalies, and crashes with the exact git SHA.

For the OoT mod: build-88 bundles **Dynamic FPS** enabled by default. CPU Clock `Normal` is recommended when evaluating it. The mod has not been validated universally at all frame rates.

### Next diagnostic if RADV crashes again

Run under GDB, stop on SIGSEGV, inspect the current thread and backtrace. If it again stops in `VkPipelinePrebu` -> `libvulkan_radeon.so`, capture a stack and optional shader dump. Do **not** allow a cache doctor to remove random entries when there is no new shader record. No ROM, keys, extracted shaders or personal data should be committed to the public fork.

## Known limitations of this audit

The combined profiles have **not** been compiled or executed on RX 6600 at the time of writing. GitHub repository write access was denied (`403 Resource not accessible by integration`), so the branch and commits must be created and pushed from the owner's terminal. Each cherry-pick may conflict if the upstream PR has changed or the fork's base moves. Stop, inspect and resolve properly instead of silently skipping a source change.
